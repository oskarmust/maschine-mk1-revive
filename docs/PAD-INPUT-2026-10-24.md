# Intermittent global pad input dropout

Local evidence: `diagnostics/20261024-211940-raw-pads/ep4-test-213641.bin`.
The capture contains 36,522 timestamped 64-byte EP4 reports over 50 seconds.
Every ADC pass contains each pad ID exactly once. Each LE word is
`pad_id << 12 | pressure`. Report starting IDs change during normal operation.

The old decoder dropped rotated reports and treated identical ADC passes as
non-pad scan data. At capture seconds 35 through 38 it emitted no pad callbacks,
despite 1,364 frames containing pressure above 300. The replacement emits all
2,198 callbacks in that interval, assigning values by pad ID.

An initial attempted fix forwarded only phase-zero exact-rest frames. This was
insufficient and was withdrawn. Its synthetic tests established only that
chosen behavior, not the actual USB packet meaning.

Validation:

- `sh tests/run-pad-release-test.sh`: 512 strike/release cycles across all 16
  starting IDs, all pads, equal/unequal ADC passes; malformed ID sets rejected.
- `tests/replay-pad-capture.c` runs the real USB dispatcher without hardware.
- Before/after outputs and counts retained alongside the capture.
- Bridge compiled with clang, CoreFoundation, IOKit and CoreMIDI.
- Installed in `/Applications/MK1 Revive.app`; USB and instance handshake
  verified. User repeated the physical pad test and confirmed the interruption
  disappeared. Log sample: 281 hits, 281 releases, zero IPC send failures.

Optional `MK1_PAD_CAPTURE` retains a circular 16 MiB raw report file. Records are
72 bytes: LE uint64 uptime nanoseconds, then 64 original bytes. Sort timestamps
after wrapping. Snapshot this file immediately after a failure before replay.
`MK1_PAD_TRACE=1` logs IPC pad send results without tracing all USB transfers.
